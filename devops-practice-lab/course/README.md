# Course index

Work through the numbered modules in order. Files named `exercise.*` are yours to
change. Production-like reference assets live under `app/`, `platform/`, and
`infra/`; lessons point to only the relevant lines so you do not need to
understand the whole system at once.

```text
00 workstation and Linux
 -> 01 networking and scripting
 -> 02 containers
 -> 03 CI/CD
 -> 04 infrastructure and cloud
 -> 05 observability and incidents
 -> 06 Kubernetes fundamentals
 -> 07 capstone
```

For every exercise: observe before changing, form one hypothesis, make the
smallest change, verify it, then record what proved or disproved the hypothesis.

## Maintainer convention

- A module teaches one coherent operational capability.
- Put a worked example before an exercise and an automated check after it.
- Keep cloud work optional; never make credentials necessary for local checks.
- Failure scenarios must be reversible through a documented command.
- Do not put target-employer information anywhere in this course.
